2. "질문하기" 버튼 하나가 지나가는 길

  1. 사용자가 채팅창에 질문을 쓰고 보내요. HTMX가 POST /chat/send/를 보내요.
  2. nginx가 HTTPS를 풀고 장고에게 넘겨요.
  3. chat/views.py가 로그인 여부와 오늘 사용 횟수를 확인해요(비용 보호).
  4. services.py가 질문을 임베딩해서 pgvector에서 비슷한 문서 조각 5개를 찾아요.
  5. 조각 + 질문을 OpenAI에 보내고, 답이 오는 대로 한 글자씩 화면에 흘려보내요(스트리밍).
  6. 다 끝나면 질문 · 답 · 토큰 수를 DB에 저장해요. 대시보드가 이걸 집계해요.

3. 폴더 구조 (17장 쇼핑몰 구조를 그대로 확장)

final-project/
├── config/              # settings는 base / dev / prod로 나누면 편함
├── accounts/            # AbstractUser로 시작 (17장처럼 처음부터!)
├── documents/           # 모델: Document, Chunk(embedding 벡터)
├── chat/                # 모델: Conversation, Message / 뷰: 스트리밍
├── dashboard/           # annotate · aggregate로 집계 (8장)
├── core/services/       # llm.py, rag.py — 뷰는 얇게, 로직은 여기
├── templates/base.html  # 공통 틀 + HTMX
├── static/
├── tests/               # 기능 하나에 테스트 하나, LLM은 가짜(mock)로
├── compose.yaml         # web + db (+ nginx, worker)
├── Dockerfile
├── .env.example         # 진짜 .env는 절대 커밋 금지
└── .github/workflows/ci.yml

ChatGPT Plus $40기획 · 코드 도움팀 공용 프롬프트 메모를 만들어 같이 쓰기

8. 자주 터지는 일과 미리 막는 법

위험미리 막기
마지막 주에 배포가 안 됨2주차 첫 배포, 이후 매주 배포
API 키가 GitHub에 올라감.env는 .gitignore, 키는 서버 환경변수. 올라갔으면 즉시 키 폐기
사용자 모델을 나중에 바꾸려다 DB가 꼬임1주차에 AUTH_USER_MODEL 커스텀 User로 시작(17장)
같은 파일을 여럿이 고쳐 충돌앱(폴더) 단위로 담당자 나누기, 기능마다 브랜치 + PR
LLM 응답이 느려 시연이 어색함스트리밍 + 시연 질문 미리 테스트 + 녹화본 준비
강사님 자료 · 남의 데이터 유출저장소는 비공개로 시작, 공개 전 교재 코드 · 개인정보 확인
