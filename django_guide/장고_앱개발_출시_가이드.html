장고로 만든 앱은 어떻게 세상에 나갈까?

수업에서 배우는 화면 구현 → Django → 리눅스 → 클라우드가 하나의 길로 이어져 있다는 걸 그림으로 정리했어요. 마지막엔 최종 프로젝트에 쓸 조합을 추천합니다.

1. 앱의 큰 그림: 장고는 가운데

이 과정에서 말하는 "앱"은 대부분 AI 기능이 들어간 웹 서비스예요. 장고는 그 한가운데에서 요청을 받아 판단하고, 꺼내 오고, 돌려주는 서버를 맡아요. 상자를 눌러 보세요.

⇄
⚙️ 서버 = Django
⇄
🗄️ 저장 · AI
상자를 누르면 여기에 설명이 나와요.
💡

Streamlit은 화면과 로직이 한 파일에 섞여 있어서 혼자 쓰는 데모에 좋아요. 장고는 화면 · 서버 · 데이터를 나눠서 여러 사람, 로그인, 오래 남는 데이터를 감당해요. 그래서 "출시하는 서비스"에 맞아요.

2. 장고로 앱을 만드는 두 가지 방식

수업에서 배운 MTV 방식 그대로예요. 장고가 화면(HTML)까지 직접 만들어 보내요.

브라우저→urls→views→models→템플릿 HTML→브라우저

요즘은 여기에 HTMX를 붙여서 "버튼 누르면 그 부분만 바뀌는" 화면을 React 없이 만들어요.

좋은 점빠르다 · 팀원 모두 파이썬만 알면 된다 · 배운 걸 그대로 쓴다
아쉬운 점스토어에 올리는 휴대폰 앱으로 만들긴 어렵다

👉 8주 최종 프로젝트, 웹 서비스라면 이쪽을 추천해요.

장고는 화면 없이 데이터(JSON)만 주고받아요. 화면은 React·Next.js 웹이나 Flutter·React Native 앱이 따로 그려요.

웹 / 앱 화면→/api/chat/→Django(DRF)→{"answer": "…"}→화면이 그림
좋은 점휴대폰 앱과 웹이 서버 하나를 같이 쓴다 · 역할이 깔끔히 나뉜다
아쉬운 점프론트엔드를 따로 배워야 하고 일이 두 배 · 로그인(토큰) 처리가 더 복잡

👉 "휴대폰 앱이 꼭 있어야 하는" 기획일 때만 고르세요.

3. 휴대폰 앱 안에 장고가 들어가나요?

아니요! 이게 제일 많이 헷갈리는 부분이에요. 휴대폰에 설치되는 앱(.apk / .ipa)은 Flutter나 React Native로 만든 화면 프로그램이에요. 장고는 인터넷 저편 AWS 서버에서 돌아가고, 앱은 그 서버에 "질문 보내 줘", "답 줘" 하고 말을 걸어요.

📱 휴대폰 앱── 인터넷(HTTPS) ──▶☁️ AWS의 Django──▶🤖 LLM
그래서 웹으로 먼저 만든 장고 서버는 나중에 휴대폰 앱을 붙여도 그대로 써요. 서버를 다시 만들 필요가 없어요.

4. 요즘 많이 쓰는 기술 (2025~2026)

"최신"이라고 다 쓸 필요는 없어요. 카드 아래 언제 쓰나를 보고 우리 기획에 필요한 것만 고르세요.

Django

Django 5.2 LTS · 6.0

5.2는 오래 지원되는 안정판(수업 버전). 2025년 말 나온 6.0에는 백그라운드 작업(django.tasks), 템플릿 조각(partials), 보안 정책(CSP) 기본 지원이 들어왔어요.

언제? 팀 프로젝트는 5.2로 시작하면 안전해요.

Django

async 뷰 + 스트리밍

ChatGPT처럼 답이 한 글자씩 흘러나오게 하려면 비동기 뷰와 StreamingHttpResponse, ASGI 서버(uvicorn)를 써요.

언제? 챗봇이 들어가면 거의 필수.

화면

HTMX

HTML 속성 몇 개(hx-post, hx-target)로 새로고침 없이 부분만 바꿔요. 장고 개발자 사이에서 아주 인기가 많아요.

언제? React 없이 요즘 웹처럼 부드럽게.

API

DRF · Django Ninja

DRF는 장고 API의 표준, Ninja는 FastAPI처럼 타입 힌트로 짧게 써요. 둘 다 자동 API 문서를 만들어 줘요.

언제? 휴대폰 앱이나 별도 프론트가 있을 때.

AI

RAG + pgvector

내 문서를 잘게 잘라 벡터로 저장하고, 질문과 비슷한 조각을 찾아 LLM에 같이 넣어요. PostgreSQL에 pgvector를 켜면 DB 하나로 끝나요.

언제? "우리 자료를 아는 챗봇".

AI

에이전트 · MCP

LangGraph로 여러 단계를 생각하고 도구를 부르는 에이전트를 만들고, MCP로 외부 도구(검색, 캘린더, DB)를 표준 방식으로 연결해요.

언제? 단순 Q&A를 넘어 "일을 해 주는" AI.

AI

뒤에서 처리하기

문서 분석, 이미지 생성처럼 오래 걸리는 일은 Celery나 django.tasks로 뒤에서 돌리고 화면엔 "처리 중"을 보여 줘요.

언제? 10초 넘게 걸리는 AI 작업.

출시

Docker + AWS + CI/CD

Docker로 내 PC와 서버 환경을 같게 맞추고, AWS(EC2·RDS·S3)에 올리고, GitHub Actions로 push하면 자동 테스트·배포.

언제? 출시하는 모든 프로젝트.

7. "휴대폰 앱처럼" 내고 싶다면: 쉬운 순서

① PWA하루 · 비용 없음

웹사이트에 manifest와 아이콘을 넣어 "홈 화면에 추가". 장고 그대로.

② Capacitor며칠 · 스토어 계정 필요

웹을 앱 껍데기로 감싸 스토어에 올려요. 화면은 웹 그대로.

③ Flutter / React Native몇 주 · 심사 있음

진짜 모바일 앱 + 장고 API(방식 B). iOS 심사는 보통 며칠, 개발자 계정 비용도 들어요.

8주 안에 ③까지 하면 AI 기능을 다듬을 시간이 부족해지기 쉬워요. ①로 시작하고, 발표 데모가 모바일이어야 할 때만 ②를 권해요.

8. 최종 프로젝트 추천 조합

🍱 우리 팀 기본 도시락
  • 서버: Django 5.2 + 템플릿 + HTMX
  • 데이터: PostgreSQL + pgvector (연습은 SQLite, 7·8장처럼 Docker로)
  • AI: OpenAI API 스트리밍 + 필요하면 RAG / LangGraph, 파인튜닝 모델은 RunPod
  • 출시: Docker compose → AWS EC2, HTTPS, GitHub Actions
  • 모바일: PWA. 꼭 필요할 때만 DRF API 추가
